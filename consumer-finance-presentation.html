Common warning patterns

Roll forward spike

The 1 to 30 DPD bucket shows higher forward roll than last month, meaning more accounts are getting worse.

Cure rate drop

Roll-backward percent falls below tolerance, meaning collections is failing to bring delinquent accounts back to current.

Vintage decay

A recent cohort hits 5 percent delinquency at MOB-3 while older cohorts only crossed that line at MOB-6.

Portfolio Quality Report

The Consumer PQR.

An Excel workbook generated from the same queries that power the dashboard. Same scope, same numbers, downloadable for offline analysis.

What it is

A 14-sheet workbook

Built client-side via ExcelJS from the same Supabase queries the dashboard uses. Every sheet is a flat, pivot-ready dataset. Cells are formatted as currency, percent, or number where appropriate. Tabs are colour-coded.

ExcelJS.xlsxTab coloured
Why it exists

Same data, offline

Boards want PDFs, analysts want Excel. The PQR fills that gap. It honours the dashboard's scope selection, so a regional report contains only that region, and a subsidiary report contains only that subsidiary.

Convention

Time-series sheets share a single utility, pivotTimeSeries(), that turns long-format records into a metric by period grid. The result is the same structure across Group, Trade, Corporate, and Risk PQRs.

How the report is built.

The PQR uses the same query layer as the dashboard. Source data flows from LOS, LMS, and collections systems into pre-aggregated tables in Supabase. The Excel file is built in the browser.

Step 1
Source systems

LOS, LMS, and collections feeds land via /api/ingest/* with API-key auth, Zod validation, and FX conversion.

Step 2
PQR tables

Pre-aggregated tables: consumer_overall_metrics, consumer_product_metrics, roll_rate_series, vintage_points, non_starters.

Step 3
Query layer

src/lib/queries/consumer.ts. Typed Supabase queries shared by the dashboard and the PQR.

Step 4
Excel build

src/lib/excel/consumer-pqr.ts. Runs 14 queries in parallel, builds 14 sheets, triggers a download.

Running the Report
12 of 14

How to generate one.

Three steps. The scope you've selected on the dashboard decides what goes into the report.

  1. Pick the scope. Group, region, or subsidiary. The same selector that filters the dashboard determines what the report contains.
  2. Open the Consumer Finance tab. The export action is contextual, so being on Consumer Finance routes to generateConsumerPQR().
  3. Trigger the export. Fourteen queries run in parallel, the workbook is built in-browser, and a tab-coloured .xlsx downloads with a scope-stamped filename.

What each scope produces

GroupAll subsidiaries consolidated to USD via the FX rates table.Group CRO, board pack preparation

SubsidiaryA single entity, in both local currency and USD.Subsidiary CRO, local risk and product

Four people typically open the Consumer Finance tab. Each starts on a different view depending on what they're trying to learn.

Chief Risk Officer

Lands on Overview, checks Stage 2+3 share and 30+ DPD trend, then glances at Vintage to confirm new cohorts aren't decaying faster than old ones. Exports the PQR for board packs.
